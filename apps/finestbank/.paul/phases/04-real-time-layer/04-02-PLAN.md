<objective>
## Goal
Add a `LiveFeed` client component that connects via WebSocket to `/ws/live/{division_id}`, receives real-time transaction events, and renders them in a compact live section above the existing paginated transaction table on the analyst page.

## Purpose
This is the frontend half of the real-time layer. Without it, the Redis pub/sub + WebSocket backend from 04-01 has no visible effect. Together they demonstrate live financial data streaming — a key portfolio showpiece.

## Output
- `frontend/src/components/live-feed.tsx` — "use client" component; WebSocket connection lifecycle, status badge, scrollable event list
- `frontend/src/app/(dashboard)/analyst/page.tsx` — Extracts `divisionId` from JWT claims, passes `divisionId` + `token` to `<LiveFeed>`
- `frontend/.env.local.example` — Documents `NEXT_PUBLIC_WS_URL` env var
</objective>

<acceptance_criteria>

## AC-1: WebSocket connects on mount and disconnects on unmount
```gherkin
Given the analyst page renders with a valid divisionId and token
When the LiveFeed component mounts
Then a WebSocket connection is established to ws://{WS_BASE_URL}/ws/live/{divisionId}?token={token}
And when the component unmounts the connection is closed cleanly
```

## AC-2: Incoming events are prepended to the live list
```gherkin
Given a connected LiveFeed component
When the WebSocket receives a JSON message (transaction event)
Then the event is parsed and prepended to the displayed list
And the list is capped at 50 items to prevent unbounded growth
```

## AC-3: Connection status is visible
```gherkin
Given a LiveFeed component
When the WebSocket is connecting/open/closed
Then a status badge shows "Connecting…", "Live", or "Disconnected"
And the "Live" badge is visually distinct (green accent)
```

## AC-4: Analyst page passes divisionId and token to LiveFeed
```gherkin
Given an authenticated analyst with division metadata in JWT
When the analyst page server component renders
Then it extracts divisionId from sessionClaims.publicMetadata.divisions[0]
And passes divisionId and token as props to the LiveFeed client component
```

## AC-5: LiveFeed is absent if divisionId is unavailable
```gherkin
Given an authenticated user without a divisions claim in JWT
When the analyst page renders
Then LiveFeed is not rendered (graceful omission, no crash)
```

<task type="auto">
  <name>Task 1: Create LiveFeed client component</name>
  <files>frontend/src/components/live-feed.tsx</files>
  <action>
    Create frontend/src/components/live-feed.tsx as a "use client" component.

    Props interface:
    ```typescript
    interface LiveFeedProps {
      divisionId: string
      token: string
    }
    ```

    LiveEvent type (matches what the simulator will publish):
    ```typescript
    interface LiveEvent {
      id: string
      type: string        // "credit" | "debit"
      category: string
      amount: number
      currency: string
      description: string
      created_at: string
    }
    ```

    State:
    - `events: LiveEvent[]` — starts empty, max 50 items
    - `status: "connecting" | "open" | "closed"` — starts "connecting"

    useEffect:
    - Reads WS base URL: `const wsBase = process.env.NEXT_PUBLIC_WS_URL ?? "ws://localhost:8000"`
    - Constructs: `const url = \`${wsBase}/ws/live/${divisionId}?token=${token}\``
    - Creates `new WebSocket(url)`
    - Sets status on ws.onopen → "open"
    - On ws.onmessage: parse JSON, prepend to events, slice to 50
    - Sets status on ws.onclose and ws.onerror → "closed"
    - Cleanup: `return () => ws.close()`

    UI:
    - Section header row: "Live Transactions" text + status badge
      - "Connecting…" — gray badge
      - "Live" — green badge with a pulsing dot
      - "Disconnected" — red/amber badge
    - If events.length === 0 and status === "open": show "Waiting for events…" in slate-500
    - Events list: compact rows (no full table), show date/time, type badge, amount, description
      - Newest at top
      - type "credit" → green badge, "debit" → red badge (matches existing analyst page style)
      - Max height with overflow-y-auto (e.g. max-h-48)

    Avoid:
    - Do NOT import anything from the Next.js server layer (auth, headers, etc.)
    - Do NOT use useState lazy initializer for WebSocket (causes SSR mismatch)
    - Do NOT render the WebSocket URL in the DOM (token exposure risk)
    - Cap events at 50 via `setEvents(prev => [parsed, ...prev].slice(0, 50))`
  </action>
